## Decisions Made
- **Gitignore by dir contents + negation, not the dir itself.** A bare `dir/` ignore prevents git from descending, so the `!.../.extracted` negation was inert. Switched to `dir/*` + `!dir/.extracted` so the 81M of proprietary bundles stay ignored while the small marker is committable (acceptance criterion: path git-ignored AND marker exists — both satisfied).
- **The renderer is minified-bundled React** (`app.min.js` 10.5M, `cc.min.js` 9.3M, lazy chunks `46/520.min.js`). Readable anchors survive only as bound identifiers (`GestureConfiguration`, `backLightAssignment`) and string-split i18n keys (`GESTURE_AC…`). Recorded that Plan 04 should study the live app + readable `data/` rather than the JS. (Also flagged that many `osd`/`radial` grep hits in the minified chunks are mangled noise, not real names.)

## Deviations from Plan

None - plan executed exactly as written. (The gitignore approach was iterated within Task 1 to satisfy both acceptance criteria — committable marker + ignored proprietary content — but this is the task's specified behavior, not a scope deviation.)

## Issues Encountered
- **First gitignore form blocked the marker.** Ignoring the directory itself (`asar-extract/`) made git refuse to descend, so the marker negation didn't apply and `git add` reported the path ignored. Resolved by ignoring dir *contents* (`asar-extract/*`) and negating the marker. Verified: `git check-ignore` ignores `app.min.js`, `git add -n .extracted` succeeds.
- **Renderer minification** means no readable component/route tree exists in the archive — expected for a shipped Electron app. Documented as the central "how to study" guidance rather than treated as a blocker.
