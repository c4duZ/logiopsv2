# Phase 04.1 Plan 01: Options+ Reference Mining (Vocabulary, Legal, Device-DB) Summary

Distilled three owned reference specs from the local Logi Options+ Windows install: a
gesture/scroll/smart-action **vocabulary** table (pt-BR + en, every row citing its Options+
key), the **hybrid/reference-only legal boundary** with a Phase 9 packaging gate, and the
**encrypted device-DB limitation** with the live-HID++-enumeration fallback. Pure
analysis/spec phase — no daemon or GUI code, nothing copied into `src/`.

## What Was Built

- **`vocabulary.md`** — our own pt-BR + en string table for gestures (HOLD+MOVE
  up/down/left/right, CLICK, gesture-button slots, info descriptions), the
  predefinição-vs-personalizada preset model, the scroll/SmartShift/hi-res/thumbwheel family,
  and a Smart Actions preview. Each row cites its exact `strings/*.yaml` key (e.g.
  `GESTURE_ACTION_HOLD_MOVE_UP`) and includes an **"Our intended label"** column = our
  re-implementation target for Phase 4.2.
- **`legal-boundary.md`** — the hybrid/reference-only rule, a *Forbidden to bundle* table
  (app.asar content, verbatim strings, icons/art, `resources.pak`, device data, macro/integration
  content, app-match DB) with a schema-vs-content distinction, an *Allowed* list, and the
  **Phase 9 BLOCKING legal-asset audit** as an explicit release blocker (cross-linked to
  ROADMAP `09-02-PLAN.md` / PKG-02).
- **`device-db-limitation.md`** — documents the encrypted `devices_*.json` header
  (`key-id`/`file-sha` + binary blob, keys `firmware.pem` / `logitech-lap-public.pem`), the
  explicit no-decryption stance (legal + futile), and the **live HID++ enumeration** fallback
  (the daemon's existing `_addFeature` probing) plus public DBs (Solaar/libratbag). Forward
  note bars phases 4.2/5–8 from depending on the encrypted files.
