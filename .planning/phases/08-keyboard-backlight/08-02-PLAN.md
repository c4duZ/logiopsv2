## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HID++ device -> daemon | The LED feature's response/broadcast reports are untrusted hardware input parsed by the new wrapper. |
| D-Bus client -> daemon | A logiops-group GUI calls SetBrightness/SetEffect with attacker-influenceable values. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Information Disclosure / DoS | Backlight::getState decode of a HID++ response | mitigate | Length-check before indexing (Long report + feature()!=0 + paramEnd-paramBegin>=N), mirroring BatteryStatus::decodeStatus (ACCESS-04). Short/unresolved report -> safe unknown state, never out-of-bounds read. |
| T-08-02 | Tampering | IPC SetBrightness/SetEffect params | mitigate | Clamp/validate every incoming value (brightness range, effect id allowlist) at the IPC boundary before building the param vector, mirroring SmartShift::IPC::setTorque's 1..100 clamp. |
| T-08-03 | Elevation of Privilege | .Backlight interface reachable by logiops group | accept | Same access path as every existing feature (Phase 1 group policy); live setters mutate device state only — persistence to /etc/logid.cfg still requires the polkit-gated Configuration::save() (ACCESS-02). No new privilege surface. |
</threat_model>
