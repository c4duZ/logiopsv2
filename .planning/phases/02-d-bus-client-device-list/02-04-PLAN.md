<objective>
Assemble the running app: a `QGuiApplication` + `QQmlApplicationEngine` window, a `DaemonConnection` that connects to the daemon on the SYSTEM bus, enumerates devices, subscribes the live `.Devices`/`.Device` signals into `DeviceModel` (no polling, CONF-03), distinguishes the four screen states via a C++ enum, and auto-reconnects on `NameOwnerChanged`. The QML shell renders the sidebar device list + read-only detail pane and the four distinct full-window states, following the system light/dark theme and the UI-SPEC tokens.

Purpose: the user opens the app and sees their devices update live (DEV-01/03/04), with clear separate messages for empty/loading/daemon-down/access-denied.
Output: `main.cpp`, `DaemonConnection.{h,cpp}`, the QML shell (Main/Theme/DeviceList/DeviceDelegate/DetailPane + 4 state screens), mouse/keyboard SVGs, CMake executable + QML module wiring.

This plan has a human-verify checkpoint (visual + live behavior). Battery DISPLAY is deliberately NOT here — Plan 05 adds it after the daemon battery (Plan 02) lands.

- `class DaemonConnection final : public QObject` owning a `DeviceModel* _model` (created/owned here or injected), the generated `PizzaPixlLogiOpsDevicesInterface* _devices`, a `QDBusServiceWatcher* _watcher`, a `QMap<QString, PizzaPixlLogiOpsDeviceInterface*> _deviceProxies`, and the `ScreenState`/Q_PROPERTY from the <interfaces> block.

- `enumerate()`: async `_devices->Enumerate()` via `QDBusPendingCallWatcher` (no blocking). On reply:
  - error name == `org.freedesktop.DBus.Error.AccessDenied` (or whatever live verification shows) -> `setScreenState(AccessDenied)`.

  - success, 0 paths -> `Empty`; >=1 -> for each path call `addDevice(path)`, then `Populated`.
- `addDevice(QDBusObjectPath path)`: create a `PizzaPixlLogiOpsDeviceInterface` for `(service, path.path(), bus)`, async-read `name()/productID()/active()`, then `_model->onDeviceAdded(path.path(), name, pid, active)`; connect that proxy's `StatusChanged(bool)` to a lambda calling `_model->onStatusChanged(path.path(), active)`. Store the proxy in `_deviceProxies`.
- Connect `_devices` `DeviceAdded(QDBusObjectPath) -> addDevice` and `DeviceRemoved(QDBusObjectPath)` -> remove the proxy + `_model->onDeviceRemoved(path)`; recompute Empty/Populated.
- `onDaemonDown()`: `_model->clear()`, delete per-device proxies, `setScreenState(DaemonDown)`.
- `onDaemonUp()` / `Q_INVOKABLE void retry()`: tear down stale proxies, `_model->clear()`, re-`enumerate()` — this is the no-restart reconnect (DEV-03/CONF-03). `retry()` is the "Retry connection" CTA target.
- `Q_INVOKABLE void copyUsermodCommand()`: `QGuiApplication::clipboard()->setText("sudo usermod -aG logiops " + qEnvironmentVariable("USER"))` for the access-denied CTA.

Add `DaemonConnection.cpp` to `logiops-gui-lib` sources in CMake. Use `QDBusPendingCallWatcher` everywhere (Pitfall 4 — never block the UI thread). Treat all paths/names as opaque; guard empty replies.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GUI client -> system bus (pizza.pixl.LogiOps) | The GUI is unprivileged; access is enforced by the Phase 1 group=logiops D-Bus policy |
| daemon-supplied strings -> QML rendering | Device Name/path rendered as text; must not be interpreted as markup/format |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Spoofing | GUI trusting a rogue owner of the bus name | accept | Phase 1 system-bus policy restricts owning the name to root; GUI binds only that well-known name on systemBus() |
| T-02-12 | Elevation | GUI attempting privileged action / hidraw | mitigate | GUI is a pure D-Bus client; no hardware access; no privileged methods called this phase (V4 access control stays in the policy) |
| T-02-13 | Info disclosure | clipboard write of usermod command | accept | The command is non-secret onboarding guidance; QClipboard write is user-initiated via the Copy CTA |
| T-02-14 | Tampering | device Name containing markup rendered in QML Text | mitigate | Render Name via Text with `textFormat: Text.PlainText` (no RichText), never via a format-string |
</threat_model>
