## Decisions Made
- Rows are the only state, mutated solely by slots (CONF-03 single-source-of-truth; the model never reconstructs from a persisted snapshot).
- Stable sort key = trailing `/devices/N` nickname integer parsed from the object path, so value-change ticks never reorder.
- `kindFromPid` is intentionally minimal (a handful of known keyboard PIDs, default Mouse) for v1; the MX Master 4 PID `0x4082` resolves to Mouse(0) as the test requires.
- Battery slot/roles present-but-unwired; Plan 05 wires `onBatteryChanged` to the daemon's `BatteryChanged` and adds battery members to `logid_device.xml`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] XML comments silently broke qdbusxml2cpp, producing empty proxies**
- **Found during:** Task 1 (proxy generation)
- **Issue:** The first version of both introspection XML files carried descriptive comments containing `--` (from `--system`/`--xml-interface` busctl examples) and `<` (from `shared_ptr<object>`). Both are invalid inside XML comments (`--` is illegal in `<!-- -->`); qdbusxml2cpp's parser silently rejected the documents and emitted **empty** proxy classes ("No relevant classes found"), so the typed-proxy deliverable was missing even though the lib still built.
- **Fix:** Reworded both comment blocks to valid XML (removed `--` double-dashes and angle brackets), keeping the busctl/marshalling guidance as plain prose. Re-ran qdbusxml2cpp -> both `PizzaPixlLogiOps*Interface` classes now generate with the full method/property/signal surface.
- **Files modified:** src/logiops-gui/dbus/logid_devices.xml, src/logiops-gui/dbus/logid_device.xml
- **Verification:** `grep "class .*Interface"` on the generated headers now shows both classes; `Enumerate`, `DeviceAdded/Removed`, `name()/productID()/active()`, `StatusChanged` all present; lib builds clean under -Werror.
- **Committed in:** f445237 (Task 1 commit)

**2. [Rule 3 - Blocking] Task 2 model files committed with Task 1 (CMake configure coupling)**
- **Found during:** Task 1 commit
- **Issue:** The Task 1 CMakeLists change adds `DeviceModel.cpp` to `target_sources` and drops `placeholder.cpp`. CMake cannot configure/build `logiops-gui-lib` if `DeviceModel.cpp` is absent, so the model source had to exist at the same commit as the CMake change.
- **Fix:** Committed `DeviceModel.{h,cpp}` together with the XML + CMake wiring in `f445237`. The TDD RED baseline (DeviceModelTest.cpp) already existed from Plan 01, so the RED->GREEN transition is intact; only the GREEN code landed in a single coupled commit rather than a separate Task 2 commit.
- **Files modified:** src/logiops-gui/DeviceModel.h, src/logiops-gui/DeviceModel.cpp
- **Verification:** `ctest -R device_model` GREEN (8/8 cases); full suite 5/5.
- **Committed in:** f445237
