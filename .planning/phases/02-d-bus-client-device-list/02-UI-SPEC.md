# Phase 2 — UI Design Contract

> Visual and interaction contract for the Qt 6 + QML app shell and the live, signal-driven device list of "Logi Options+ for Linux".
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack is LOCKED** (research STACK.md, CONTEXT.md): Qt 6 + QML / Qt Quick Controls 2, C++20, custom-skinned for Options+ fidelity, following the system light/dark theme. The shadcn/web-registry sections of the GSD template are **not applicable** to a native Qt app and are recorded as such; everything else is adapted to QML primitives (`Window`, `SplitView`/`RowLayout`, `ListView`, `delegate`, `Behavior`, `states`/`transitions`).
>
> **Scope anchor:** app shell (single window: device sidebar + detail pane) + live device list (name/model, battery %+charging, connection status) + four screen states (empty / loading / daemon-not-running / access-denied onboarding). **No** device configuration UI, **no** per-model device renders (generic mouse/keyboard icons only). Those are Fase 3 / UI-01.
>
> **Verification flag (web tools were unavailable in research):** the Options+-flavored palette, list-item anatomy, and motion timings below are based on general knowledge of Logitech Options+. They are intentionally an *own identity*, not a pixel copy. Items marked **[verify-against-real-Options+]** should be re-checked against real Options+ screenshots before Fase 3 hardens the visual language. None of these flags block Phase 2 implementation.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native Qt 6 + QML — shadcn/web registry not applicable) |
| Preset | not applicable |
| Component library | Qt Quick Controls 2 with a **custom style** (NOT Material/Universal/Fusion defaults). Use `qtquickcontrols2.conf` → `Style=Custom` (or per-control inline `contentItem`/`background` overrides). Controls 2 Basic style is the customizable base. |
| Icon library | Inline SVG via **QtSvg** (`Image` with `source: "qrc:/icons/*.svg"`), `sourceSize` set for crispness, recolored via `layer` + `ColorOverlay` or pre-themed asset pairs. Generic device kinds (mouse, keyboard) + battery glyphs + status glyphs only this phase. |
| Font | **System default font, following the desktop** — `Qt.application.font` (do NOT bundle a font; Options+ fidelity here means "feels native + clean", and the daemon target is Debian/GNOME/KDE where the system sans-serif — Cantarell / Noto Sans / Inter-like — is already clean). Sizes/weights declared below in points→px. **[verify-against-real-Options+]** Options+ ships its own typeface; we deliberately follow the system font instead for Linux nativeness. |
| Theme source | System light/dark via Qt. Detect with `Qt 6.5+ Application.styleHints.colorScheme`; on the verified target Qt **6.4.2** (no `colorScheme` enum), detect via the platform palette: derive dark-mode from `palette.window` luminance (`window.hslLightness < 0.5 → dark`) and subscribe to `paletteChanged`. All tokens below are defined as a light/dark pair resolved at runtime — never hard-code a single mode. |
| Rendering model | C++ owns all state (`QAbstractListModel` device model + screen-state enum exposed as a context property/`Q_PROPERTY`). QML renders only — **zero business logic in QML/JS** (CONTEXT.md decision). |

## Spacing Scale

8-point scale (all multiples of 4). In QML these are exposed as a singleton `Theme.spacing` (`Theme.qml` / `pragma Singleton`) so delegates and panes share one source.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, badge inner padding, battery-glyph-to-% gap |
| sm | 8px | Compact vertical rhythm inside a list item, chip padding |
| md | 16px | Default element spacing, list-item horizontal padding, detail-pane field gaps |
| lg | 24px | Sidebar/detail-pane content inset, section padding, empty-state vertical rhythm |
| xl | 32px | Major layout gaps, gap between detail-pane header block and body |
| 2xl | 48px | Empty/error illustration-to-text separation, onboarding block breaks |
| 3xl | 64px | Top inset for centered full-pane states (empty / daemon-down / access-denied) |

Exceptions:
- **List-item row height: 56px** (not on the 4-scale by accident — it is 7×8; deliberate touch/click target ≥ 44px with comfortable padding). Icon container within it is **40px**.
- **Hit targets:** any clickable row or icon-button must be ≥ **40px** tall/wide (Fitts/keyboard comfort); the 56px row satisfies this.
- **1px hairline dividers** (between list items / between sidebar and detail pane) are the only sub-4 value, used as borders not spacing.

## Typography

System font (`Qt.application.font` family). Sizes are declared in **px** (set `font.pixelSize` for deterministic cross-DPI sizing; Qt scales by `devicePixelRatio`). **Exactly 4 sizes, exactly 2 weights** (Regular 400 + Medium/Semibold 600). No italics, no third weight.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 28px | 600 | 1.2 | Detail-pane device name (selected device header); empty/error state primary heading |
| Heading | 20px | 600 | 1.25 | Section labels in detail pane (e.g. "Battery", "Connection"), sidebar group label |
| Body | 16px | 400 | 1.5 | Device name in list item, descriptive/onboarding paragraph copy |
| Label | 14px | 600 | 1.4 | Model sub-line (muted), battery %, status badge text, button labels |

Notes:
- Battery percentage uses **Label 14px / 600** with **tabular figures** if the system font supports them (`font.features` or fall back to default) so the number doesn't horizontally jitter as it updates live — supports the no-flicker contract.
- Muted/secondary text (model sub-line, "—" unknown battery) uses Label size at the **muted foreground** color (below), not a lighter weight.

## Color

Options+-flavored **own identity**, defined as a **light/dark pair**, layered onto the system palette so window-manager accent/contrast settings still feel native. The 60/30/10 split maps to: dominant = detail-pane/canvas surface, secondary = sidebar + cards, accent = selection + charging + primary CTA only.

**Light theme**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5F6F8` | App canvas / detail-pane background |
| Secondary (30%) | `#FFFFFF` | Sidebar surface, list-item card, raised panels (with `#E3E6EB` 1px hairline) |
| Accent (10%) | `#2D7DF6` | **Reserved list below** |
| Destructive | `#D93535` | Not used in Phase 2 UI (no destructive actions this phase); reserved token for Fase 3+ |
| Foreground | `#1B1D21` | Primary text |
| Muted foreground | `#6B7280` | Model sub-line, unknown "—", secondary copy, offline label |
| Success / charging | `#2BA84A` | Charging indicator + ≥ healthy battery fill |
| Warning | `#E8A23D` | Low-battery fill (≤ 20%, see thresholds) |

**Dark theme**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1C1E22` | App canvas / detail-pane background |
| Secondary (30%) | `#26292E` | Sidebar surface, list-item card, raised panels (with `#34383F` 1px hairline) |
| Accent (10%) | `#4C92FF` | **Reserved list below** (lightened for dark-mode contrast) |
| Destructive | `#F0635F` | Reserved for Fase 3+ |
| Foreground | `#ECEEF1` | Primary text |
| Muted foreground | `#9AA1AC` | Model sub-line, unknown "—", secondary copy, offline label |
| Success / charging | `#46C46A` | Charging indicator + healthy battery fill |
| Warning | `#F0B252` | Low-battery fill (≤ 20%) |

**Accent reserved for** (explicit list — accent is NEVER applied to all interactive elements):
1. The **selected device** row in the sidebar (left accent bar 3px + tinted background at ~12% accent alpha).
2. The **keyboard-focus ring** (2px accent outline) on focusable elements.
3. The **primary CTA** in onboarding/error states ("Open a terminal" is informational; the actual primary CTA is **"Copy command"** and **"Retry connection"** — see copywriting).
4. The **charging bolt** uses Success green, NOT accent — accent stays selection/focus/CTA only.

Contrast: every text/background pair above meets **WCAG AA (≥ 4.5:1 for body, ≥ 3:1 for ≥ 20px/600)**. Accent on its tinted-12% selection background keeps text at Foreground (not accent) to preserve contrast. **[verify-against-real-Options+]** exact accent hue — Options+ uses a Logitech blue; `#2D7DF6` is a close, accessible stand-in.

Battery fill thresholds (numeric % always shown alongside, per CONTEXT decision — no predictive estimate):
- `> 20%` → Success/charging green fill (or Foreground-muted track when not the point of emphasis)
- `≤ 20%` → Warning amber fill
- `charging == true` → overlay charging bolt glyph in Success green regardless of level
- `unknown` (device doesn't report `WirelessDeviceStatus`) → no fill, show **"—"** in Muted foreground, no warning color

## Copywriting Contract

All copy in **English (en)**, sentence case, plain and non-jargony. No emoji. (Owner is Brazilian; project default language has been English across PROJECT/REQUIREMENTS — keep en for v1, i18n is out of scope.)

| Element | Copy |
|---------|------|
| Primary CTA (access-denied) | **"Copy command"** (copies `sudo usermod -aG logiops $USER` to clipboard) |
| Primary CTA (daemon-not-running) | **"Retry connection"** |
| Empty state heading | **"No Logitech devices found"** |
| Empty state body | **"Connect a Logitech mouse or keyboard — or turn on a paired one — and it'll show up here automatically."** |
| Error state (daemon-not-running) | Heading: **"Can't reach the logid service"** / Body: **"The logid background service isn't running. Start it, then retry."** + secondary hint (Label, muted): **"Try: `sudo systemctl start logid`"** + **"Retry connection"** button |
| Error state (access-denied onboarding) | Heading: **"You're not in the logiops group yet"** / Body: **"To control your devices, add your user to the `logiops` group and sign back in."** + a **monospace command block** showing `sudo usermod -aG logiops $USER` with a **"Copy command"** button, followed by Label-muted note: **"Then log out and back in (or reboot) for it to take effect."** |
| Loading state | Heading (optional, may be skeleton-only): **"Looking for your devices…"** (single ellipsis char, no animated dots in text) |
| Destructive confirmation | **None in Phase 2** — this phase is read-only status display. No device configuration, no destructive actions. (Destructive-action confirmation contract is deferred to Fase 3 reset/restore-defaults.) |

State distinction (CONTEXT.md requires these be *separate, clear* messages — never collapse into one generic error):
- **No devices** (connected to daemon, zero devices) → Empty state above.
- **Daemon not running** (bus name `pizza.pixl.LogiOps` has no owner / connection failed) → daemon-not-running error above.
- **Access denied** (connected but D-Bus policy rejects: `org.freedesktop.DBus.Error.AccessDenied` / not in `logiops` group) → onboarding above.
- These are driven by the C++ screen-state enum, not inferred in QML.

Microcopy for list-item states:
- Offline badge: **"Offline"** · Sleeping badge: **"Sleeping"** · Unknown battery: **"—"** (em-dash, muted).
- Connection (online) needs no badge — absence of a badge means connected/awake (reduce visual noise).

## Layout Contract

| Property | Value |
|----------|-------|
| Window type | Single `ApplicationWindow`, standard titlebar (native decorations; no custom chrome this phase). |
| Default size | **960 × 640** (logical px) |
| Minimum size | **720 × 480** — below this the sidebar may collapse but content must stay legible |
| Sidebar (device list) | Fixed-ish width **280px** (min 240, max 360 if user-resizable via `SplitView`). Surface = Secondary color. Holds the `ListView` of devices + optional small header label. |
| Detail pane | Flexible remainder. Surface = Dominant color. This phase: **read-only** device status (large device icon, Display-size name, model sub-line, battery block, connection block). Configuration tabs are a Fase 3 concern — leave vertical room but do NOT scaffold config controls. |
| Split | `SplitView` (horizontal) or `RowLayout` with a 1px hairline divider between sidebar and detail. Divider color = the theme hairline. |
| Full-pane states | Empty / loading / daemon-down / access-denied take over the **entire window** (sidebar + detail), centered content, max content width **480px**, vertical-centered with 3xl top breathing room. They are not shown *inside* the detail pane while a populated sidebar exists — they are whole-window states because they describe a connection/population condition, not a per-device condition. |
| Responsive | At ≥ 720px width: side-by-side. The window is a desktop settings panel — no mobile/breakpoint matrix needed. If a future narrow width is hit, sidebar collapses to an overlay drawer (out of scope to build now; just don't hard-block it structurally). |
| Empty-detail (devices exist, none selected) | On launch with ≥1 device, **auto-select the first device** so the detail pane is never blank. If selection is somehow cleared, detail pane shows a quiet "Select a device" muted Body line (not a full error state). |

## Device List Item — Anatomy & States

One `ListView` `delegate`, 56px row, horizontal padding `md` (16px). Layout left→right: **[icon 40px] [name/model column, flex] [battery block] [status badge?]**.

**Anatomy:**
1. **Device icon (40px container, ~28px glyph):** generic per-kind SVG — `mouse` or `keyboard` — chosen from a C++ model role (`deviceKind`). Tinted to Foreground (or Muted when offline). No per-model artwork (Fase 3 / UI-01).
2. **Name (Body 16px/400, Foreground):** device name/model from `DeviceName` (DEV-04). Elide right on overflow.
3. **Model sub-line (Label 14px/600, Muted):** secondary identifier (e.g. "MX Master 4") when distinct from name; omit if redundant.
4. **Battery block (right-aligned):** small battery glyph + numeric **% (Label 14px tabular)** + charging bolt overlay when charging. Color per thresholds above. Shows **"—"** muted when `WirelessDeviceStatus` is unreported (DEV-02).
5. **Status badge (only when not online-awake):** a small pill — "Offline" or "Sleeping" — Label 14px, Muted text on a subtle muted-surface chip. No badge when online/awake.
6. **Selection affordance:** 3px accent left bar + 12%-accent tinted row background on the selected item.
7. **Divider:** 1px hairline between rows (not after the last).

**States** (a delegate must visually represent each; driven by model roles `connectionState` ∈ {online, offline, sleeping, unknown}, `batteryPercent`, `charging`, `batteryKnown`, `selected`, `hovered`, `focused`):

| State | Visual treatment |
|-------|------------------|
| **Online / awake** | Full opacity. Icon + name Foreground. Battery colored per threshold. No badge. |
| **Offline (unplugged / receiver lost)** | Row at **~55% opacity** (dimmed, but stays in list — CONTEXT decision). Icon + name Muted. "Offline" badge. Battery shows last-known % in Muted (or "—" if never known). Still selectable. |
| **Sleeping (`_awake == false`)** | Row at **~70% opacity**. "Sleeping" badge. Battery shown if known, else "—". Still selectable; waking the device transitions it to online with a fade (no flicker). |
| **Unknown battery** | Battery glyph in Muted + **"—"**, no warning color, no charging bolt. Independent of connection state. |
| **Hover** (mouse) | Row background lifts to a subtle hover tint (≈6% Foreground overlay), cursor `PointingHandCursor`. |
| **Keyboard focus** | 2px accent focus ring inset on the row, independent of hover/selection. |
| **Selected** | Accent left bar + tinted background (see Anatomy 6). Selected + offline = tint + dim combine. |

## Interaction Contracts

| Interaction | Contract |
|-------------|----------|
| **Select a device** | Click or keyboard-activate a sidebar row → C++ sets `currentIndex`; detail pane binds to that device's roles. Selection is **single-select**. Selecting is instant; the detail pane cross-fades content over **150ms** (`Behavior on opacity` / `Fade` transition), never a hard cut, never a layout jump. |
| **Live battery / status update (no flicker)** | The model emits `dataChanged(index, {BatteryRole|ConnectionRole|...})` on D-Bus signal — **never** `beginResetModel`/full reload for a value change (that would flicker the whole list). The delegate binds each field independently so only the changed text/fill repaints. Battery % uses tabular figures so width is stable. Color/fill changes animate via `Behavior on color`/`Behavior on width` over **200ms** ease-out. **Contract: a battery tick or status flip must not move any row, re-sort the list, or blink the icon.** |
| **Hotplug add** | New device → `beginInsertRows`/`endInsertRows`. The new delegate animates in: `ListView.add` transition — fade `0→1` + slide-down **8px→0** over **220ms** ease-out. Sort order stable (see below) so existing rows don't jump. |
| **Hotplug remove** | Device truly gone (not just offline — offline stays dimmed) is rare this phase; receiver-unpaired removals use `beginRemoveRows`/`endRemoveRows` with `ListView.remove` transition — fade `1→0` + collapse height over **200ms**. If the removed device was selected, selection moves to the nearest remaining row (or to empty state if none). **Default: connection loss = dim-in-place (offline state), NOT removal** — only genuine unpair/unplug-of-receiver removes the row. |
| **Daemon restart / crash reconnect** | On `NameOwnerChanged` (owner lost) → screen-state flips to daemon-not-running (or a brief reconnect banner if a quick re-acquire is expected). On owner re-acquired → auto re-enumerate and rebuild the model; the list repopulates with add transitions. **No app restart, no manual refresh button required** (DEV-03 / CONF-03). C++ owns the reconnect loop with backoff; QML just reflects the enum. |
| **Sort order** | Stable, deterministic ordering owned by C++ (e.g. by daemon device path / nickname). **Battery and connection changes must never re-sort** (re-sorting on every battery tick is the classic flicker bug — explicitly forbidden). |
| **Sleeping → wake / offline → online** | Driven by signal → `dataChanged`. Row animates opacity back to full over **200ms**; badge fades out. No row reorder. |
| **Loading → populated** | Skeleton/spinner state holds until the first enumeration completes; then cross-fade (150ms) into the populated shell. Avoid empty-flash: don't show the empty state during initial enumeration — only after enumeration confirms zero devices. |
| **Copy command (onboarding)** | "Copy command" writes `sudo usermod -aG logiops $USER` to the clipboard via C++ (`QClipboard`); button label briefly swaps to **"Copied"** for ~1.5s then reverts. |
| **Retry connection (daemon-down)** | Triggers a C++ reconnect attempt immediately; button shows a brief inline spinner while attempting; on failure stays on the daemon-down state. |

**Motion budget (global):** all transitions **120–250ms**, ease-out (`Easing.OutCubic`). No bounce, no spring overshoot for status/data changes (it reads as instability for a live monitor). Respect a reduced-motion preference if the platform exposes one (fall back to instant cross-fades, keep durations ≤ 100ms or 0).

## Accessibility

| Dimension | Contract |
|-----------|----------|
| **Keyboard navigation** | Sidebar `ListView` is fully keyboard-operable: ↑/↓ move selection, Enter/Space activate, Tab/Shift-Tab move between sidebar ↔ detail-pane ↔ state-screen buttons. Onboarding/error CTAs are in the tab order. `Keys`/`KeyNavigation` wired; `ListView` `keyNavigationEnabled: true`. |
| **Focus states** | Every focusable element shows a visible **2px accent focus ring** (the accent's reserved use #2). Focus is never invisible. Initial focus on launch lands on the first device row (or the primary CTA in a state screen). |
| **Accessible roles/names** | Set `Accessible.role` / `Accessible.name` / `Accessible.description` on rows ("MX Master 4, 80 percent, charging, online"), battery, badges, and CTAs so Orca/AT-SPI announces live state. Battery/connection changes update `Accessible.name` so screen readers hear the new value. |
| **Contrast** | All pairs meet WCAG AA (declared in Color). Dimmed offline rows still keep their (muted) text ≥ 3:1; never rely on opacity alone to convey offline — the **"Offline" text badge** carries the meaning too (color/opacity is not the sole signal). |
| **Non-color signaling** | Connection and battery state are conveyed by **text + glyph**, not color alone (offline = badge text; low battery = % number + glyph, not just amber). Charging = bolt glyph + "charging" in accessible name, not green-only. |
| **Hit targets** | ≥ 40px (rows 56px; icon buttons ≥ 40px). |
| **Text scaling** | Sizes set via `font.pixelSize` but layouts use `Layout`/anchors that reflow; elide rather than clip. Honor the system font scale where Qt surfaces it. |
| **Reduced motion** | If the platform exposes a reduced-motion hint, disable slide/fade transitions (see Motion budget). |
