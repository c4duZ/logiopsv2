    a borderless, always-on-top, input-transparent (click-through) window and moves
    it to follow the pointer, proving the core overlay mechanic on X11:
      - Always-on-top + no decorations: set `_NET_WM_WINDOW_TYPE` to
        `_NET_WM_WINDOW_TYPE_TOOLTIP` (or `_NET_WM_STATE_ABOVE` + override-redirect).
        Document which you used and why.
      - Click-through: use the XFixes shape extension to set an EMPTY input region
        (`XFixesSetWindowShapeRegion(... ShapeInput, emptyRegion)`) so pointer events
        pass through to the window beneath.
      - Follow-cursor: poll/query pointer position (`XQueryPointer`) on a short timer
        and `XMoveWindow` the overlay to the cursor (centered on it).
      - Draw a trivial filled circle (any X primitive) just to prove it is visible
        and on top.
    Provide a `spike/overlay/README.md` with the exact build command (e.g.
    `gcc x11_overlay.c -lX11 -lXfixes -o x11_overlay`) and run instructions. This is
    THROWAWAY proof code — keep it tiny and single-file; it is never linked into the
    GUI and `spike/` is excluded from the CMake build.
  </action>

  <action>
    Write a minimal Wayland client (`spike/overlay/wayland_layershell.c`) that binds
    the `zwlr_layer_shell_v1` protocol and creates an overlay-layer surface drawing a
    trivial filled shape, proving the layer-shell overlay path that wlroots/KWin
    support:
      - Use libwayland-client; bind `wl_compositor` + `zwlr_layer_shell_v1` from the
        registry. If `zwlr_layer_shell_v1` is ABSENT from the registry, print a clear
        "layer-shell UNAVAILABLE on this compositor" message and exit non-fatally —
        this absence IS the data point we need per compositor.
      - Create a `zwlr_layer_surface_v1` on the `OVERLAY` layer, anchored, drawing a
        small filled square via a shm buffer (no GPU needed).
      - Document in README.md that Wayland does NOT allow a client to globally query
        or set the cursor position, so a follow-the-pointer overlay is only possible
        where the compositor supports it (layer-shell anchoring near the pointer is
        NOT generally available) — hence the centered-popup fallback.
    Append to README.md the exact build command (e.g.
    `gcc wayland_layershell.c -lwayland-client -o wayland_layershell`, noting any
    `wayland-scanner` codegen needed for the layer-shell protocol XML, or vendoring
    the generated header). THROWAWAY — not linked into the GUI build.
  </action>
  <verify>
    <automated>test -f spike/overlay/wayland_layershell.c && grep -q "zwlr_layer_shell_v1" spike/overlay/wayland_layershell.c && echo OK</automated>
  </verify>
  <done>
    `wayland_layershell.c` binds `zwlr_layer_shell_v1` and either draws an overlay
    surface or cleanly reports its absence. README.md documents the Wayland
