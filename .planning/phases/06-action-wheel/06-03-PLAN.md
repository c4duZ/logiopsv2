<!-- WheelModel mirrors GestureModel's two-step write. Extracted contracts: -->

GestureModel is the precedent (src/logiops-gui/GestureModel.h/.cpp). It does the
strict two-step async reassign over a STABLE typed proxy + a DYNAMIC per-mode child
call. WheelModel copies this shape:
  Step 1 (stable, typed): Action.ActionWheel.SetSlice(index, type) via the generated
          PizzaPixlLogiOpsActionWheelInterface proxy (from logid_action_wheel.xml).
  Step 2 (dynamic, generic QDBusInterface): set that slice's BasicAction params on the
          per-slice child node (e.g. .Action.Keypress.SetKeys) — same generic
          QDBusInterface call GestureModel::performParamCall uses for .Gesture.<mode>.

ButtonsModel already does the Button.SetAction(type) call (src/logiops-gui/ButtonsModel)
— reuse its CID-keyed SetAction path to assign "ActionWheel" to the chosen button; do
NOT duplicate that logic, call into the existing model.

Proxy generation (src/logiops-gui/CMakeLists.txt) — add ONE line mirroring the gesture
proxy (qt_add_dbus_interface), generating PizzaPixlLogiOpsActionWheelInterface:
```cmake
qt_add_dbus_interface(GUI_DBUS_SRCS dbus/logid_action_wheel.xml logid_action_wheel_proxy)
```
The XML must declare interface name `pizza.pixl.LogiOps.Action.ActionWheel` with the
SetSlice(index:int, type:string) method and the ActiveSlice property (read-only int),
matching the daemon interface from 06-02. (Trim the introspection like
logid_action_gesture.xml — no `--` or `<` inside XML comments; that silently broke
qdbusxml2cpp in Phase 2.)

Register WheelModel in the GUI lib source list (target_sources of logiops-gui-lib),
next to GestureModel.cpp; expose it to QML the way DeviceControllerFactory/GestureModel
are exposed.
</interfaces>
