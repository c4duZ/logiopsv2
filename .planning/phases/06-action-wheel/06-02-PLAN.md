<objective>
Build the daemon half of the action wheel (architecture-locked: daemon detects +
executes, GUI renders only). Add a new `ActionWheel` Action that, while its bound
button is held, diverts raw XY, accumulates the flick vector, maps the flick angle
to one of N configured slices, and fires that slice's action on release. Each slice
holds a `config::BasicAction` (the existing reusable non-gesture action variant), so
slices reuse Keypress/ChangeDPI/CycleDPI/ChangeHost/ChangeProfile/toggles for free
(WHEEL-01). The action exposes the live active-slice index over D-Bus so the GUI
overlay can highlight the slice under the flick (feeds WHEEL-02/03).

Purpose: WHEEL-01 (configure N slices each bound to an action) + WHEEL-02 (trigger,
flick, release-to-fire) on the daemon side.
Output: `config::ActionWheel` schema node, `actions::ActionWheel`, factory
registration, and a RED-first geometry unit under `tests/phase6`.
</objective>

Action base (src/logid/actions/Action.h) — the interface ActionWheel implements:
```cpp
class Action : public ipcgull::interface {
    virtual void press() = 0;
    virtual void release() = 0;
    virtual void move(int16_t x, int16_t y) { }       // override to receive raw XY
    [[nodiscard]] virtual uint8_t reprogFlags() const = 0;
protected:
    Action(Device* device, const std::string& name, tables t = {});
    Device* _device;
    std::atomic<bool> _pressed;
    mutable std::shared_mutex _config_mutex;
};
```

GestureAction is the working precedent — copy its shape:
- `static const char* interface_name;` (e.g. "ActionWheel"); the IPC interface name
  becomes SERVICE_ROOT_NAME ".Action.ActionWheel" via the Action() base ctor.
- Constructor takes `(Device* dev, config::ActionWheel& config, const std::shared_ptr<ipcgull::node>& parent)`
  and registers D-Bus methods via the `tables` ctor arg (see GestureAction ctor:
  `{{ {"SetSlice", {this, &ActionWheel::setSlice, {...}}} }, {}, {}}`).
- `reprogFlags()` MUST return `(ReprogControls::TemporaryDiverted | ReprogControls::RawXYDiverted)`
  so the button's raw XY is diverted to move() while held (see GestureAction.cpp:221).
- press() resets accumulators; move(x,y) accumulates `_x += x; _y += y;` under a
  shared_lock; release() resolves the slice and fires.

The reusable per-slice action type already exists — config::BasicAction
(src/logid/config/schema.h:134), a variant of NoAction/Keypress/ToggleSmartShift/
ToggleHiresScroll/CycleDPI/ChangeDPI/ChangeHost/ChangeProfile. Build each slice's
runtime action with the EXISTING factory overload:
```cpp
Action::makeAction(Device* device, config::BasicAction& action,
                   const std::shared_ptr<ipcgull::node>& parent);
```

Factory registration pattern (src/logid/actions/Action.cpp:_makeAction, string
overload): add an `else if (name == ActionWheel::interface_name)` branch that sets
`config = config::ActionWheel();`. NOTE: ActionWheel is a full `config::Action`
variant (like GestureAction), NOT a BasicAction — register it in the
`makeAction(..., std::optional<config::Action>&, ...)` path exactly where
GestureAction is handled (Action.cpp:108-114), so it is reachable from a button's
SetAction("ActionWheel") but NOT nestable inside a slice (no recursion).
