# Phase 4 — UI Design Contract

> Visual and interaction contract for the **guided gesture builder** of "Logi Options+ for Linux".
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack note (unchanged from Phase 2/3):** desktop **Qt 6.4.2 + QML / Qt Quick Controls 2**
> app (`src/logiops-gui/`). No web stack — no Tailwind, no CSS, no shadcn. The shadcn/registry
> gate is **not applicable**; the Registry Safety section records this. All tokens below are
> expressed as `Theme.qml` singleton properties.
>
> **Extend, do not replace.** This phase invents **no new visual language and no new tab**.
> The gesture builder lives **inside the existing `ReassignPanel.qml`** as a new **"Gesture"**
> action category (locked CONTEXT decision), beside Keystroke / DPI / Host switch / etc. It
> reuses Phase 3's panel chrome, `CategoryRow` anatomy, live-apply model, `ConfigState`
> dirty pill, and polkit `Save`. This document RE-DECLARES the inherited tokens it relies on
> (so the checker validates one file) and ADDS only the gesture-builder component, motion, and
> copy contracts. Two new `Theme.qml` tokens are introduced (named in "New tokens"); everything
> else binds to existing `Theme.*`.
>
> **North-Star quality bar (standing owner feedback: "ridículo de feio, porém funcional").**
> The current GUI is functional but flat. This builder is the first feature that is a genuine
> *differentiator* (REQUIREMENTS "Gestures (priority differentiator)"), so it must read as
> **Options+ polish**, not skeleton. Concretely, "more Options+" here means: (1) a compact
> **4-direction cross/pad** that maps to the physical mouse motion instead of a flat list of
> "up/down/left/right"; (2) **progressive disclosure** — mode → action → granularity reveal in
> sequence, never all-at-once noise; (3) a **live plain-language preview sentence** treated as a
> first-class, emphasized UI element (the affordance that makes gestures legible), not a footnote;
> (4) a **granularity slider with a human readout** ("~1 step per X of movement"), never a raw
> HID++ number; (5) calm, interruptible motion within the inherited 120–250ms budget.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Qt Quick Controls 2, not a web design system) |
| Preset | not applicable |
| Component library | Qt Quick Controls 2 (`QtQuick.Controls`), custom-tinted via the `Theme.qml` singleton (Phase 2/3 approach). No Material/Universal/Fusion theme. |
| Icon library | In-tree monochrome single-path SVG glyphs under `src/logiops-gui/icons/`, `currentColor`-tintable. Phase 4 adds the glyphs in "Iconography" below in the same style. |
| Font | System default font (`Qt.application.font`). No bundled font; weights limited to Regular(400) + DemiBold(600). |
| Theme mode | Light/dark resolved at runtime from `SystemPalette.window.hslLightness < 0.5` (Qt 6.4.2 has no `colorScheme`). Every color token is a light/dark PAIR — bind to `Theme.*`, never hard-code. |
| Rendering model | C++ owns all state (a gesture model mirroring `ButtonsModel`'s two-step async pattern + typed proxies). QML renders only — **zero business logic in QML/JS** (locked project rule). The preview sentence is composed in C++/the model and exposed as a NOTIFYable string property; QML only displays it. |

## Typography

Existing scale — exactly **4 sizes**, exactly **2 weights**, declared in `Theme.qml`, reused **unchanged**. No new sizes or weights.

| Role | `Theme` property | Size | Weight | Line Height | Usage in this phase |
|------|------------------|------|--------|-------------|----------------------|
| Display | `displaySize` | 28px | DemiBold (600) | 1.2 | Not used inside the panel (panel header stays Heading per Phase 3) |
| Heading | `headingSize` | 20px | DemiBold (600) | 1.2 | The button name in the panel header (inherited); the **active direction label** ("Up", "Left") above the mode picker |
| Body | `bodySize` | 16px | Regular (400) | 1.5 | **The live preview sentence**; mode pill labels; action summaries |
| Label | `labelSize` | 14px | DemiBold (600) for field labels ("Mode", "Action", "Granularity"); Regular for the granularity readout + helper text | 1.4 | Section field labels, the "~1 step per X" readout, helper/empty copy in `mutedForeground` |

Rules:
- **No new sizes or weights.** Every gesture-builder string maps onto these 4 roles.
- The **preview sentence is Body 16 / Regular** at `foreground` — deliberately the most readable role in the panel (it is the feature's whole point), set on a tinted preview card so it reads as emphasized without inventing a new size/weight.
- The granularity readout ("~1 step per X of movement") is **Label 14 / Regular, tabular-stable width** (Phase 2 `TextMetrics` pattern — `font.features` tnum is Qt 6.7+, target is 6.4.2). The "X" value must not reflow as the slider drags.
- All user-facing strings wrapped in `qsTr()`.

> Net new **color hues: zero.** Phase 4 introduces no new color; it adds one *layout* token (`gestureDirCell`) and one *semantic alias* (`gestureConfigured` → `accent`). This keeps the palette identical to Phase 2/3.

**Accent reserved for (explicit list — extends the Phase 3 list for gesture surfaces; never "all interactive elements"):**
1. The **currently active direction cell** (the one being edited) — `accentTint` background + accent label.
2. A small **accent "configured" dot** on any direction cell whose gesture is not "Nothing".
3. The **selected mode pill** (`accentTint` background, accent text) among the 4 plain-language modes.
4. The **keyboard-focus ring** (2px accent) on any focused cell / pill / slider / action control.
5. The **filled portion + thumb** of the granularity slider.
6. The action-picker's **current-action accent dot** (inherited `CategoryRow` behavior, when a gesture action is chosen).

Everything else — unselected mode pills, inactive direction cells, the "Nothing" mode, action sub-rows, the panel "Close" button, the granularity track (unfilled) — uses `foreground` / `secondary` / `hairline` / `mutedForeground`, **never accent**. The preview card uses `accentTint` as a *surface* (a quiet emphasis), with its text at `foreground` for contrast — matching the Phase 2/3 "text stays foreground on accentTint" rule.

**Contrast note:** every text/background pair meets WCAG AA (≥4.5:1 body, ≥3:1 for ≥20px/600) in both light and dark, verified against the inherited token pairs. State is never conveyed by color alone — the active direction also shows its label as a Heading, the configured dot is paired with a non-default mode/action summary, and the preview sentence carries the meaning in words.

## Component & Interaction Contract

This is the prescriptive heart of the phase. The gesture builder is **one new expandable category inside `ReassignPanel.qml`**, rendered exactly like the existing `CategoryRow` entries (glyph + label + accent dot), and shown **only when the selected button reports `GestureSupport == true`** (capability-gated via Introspect, like every other section). When the gesture category is unsupported for the button, the row is **hidden** (not shown-disabled) — consistent with the project gating rule for device-kind-irrelevant capabilities.

### Entry point — new "Gesture" category row (GEST-01)
- A new `CategoryRow` labeled **"Gesture"** with a new `gesture` glyph, slotted in the CONTEXT-ordered list (placed after "Hi-res toggle", before "Disabled"). `active` when the button's current action type is `GestureAction`.
- Choosing it expands the **gesture builder** inline beneath the row (same `expanded` state machine the panel already uses for ChangeDPI/Host/Profile), with a `motionAdd` 220ms height/opacity reveal (`OutCubic`).

### 1 — Direction picker (4 cardinal cross) (GEST-01)
- A compact **3×3 grid** where the **up / down / left / right** edge-center cells are interactive (`gestureDirCell` 44px each); corners are empty; the center cell holds a small `mouse` glyph (`mutedForeground`) to anchor the spatial metaphor. This is the "more Options+" move: the user picks a *physical direction on the mouse*, not a row in a list.
- Cell states:
  - **Default**: `hairline` 1px border, transparent fill, the direction's small arrow glyph in `foreground`.
  - **Configured** (gesture ≠ "Nothing"): an **accent dot** in the cell corner (`gestureConfigured`) so all four directions' configured/empty status is legible at a glance.
  - **Hover**: `hoverTint` fill, `PointingHand` cursor.
  - **Active/editing**: `accentTint` fill + accent arrow + 2px accent ring; the rest of the builder (mode/action/granularity/preview) below binds to THIS direction.
  - **Keyboard focus**: 2px accent focus ring (arrow keys move between the 4 cells; Enter/Space activate).
- Selecting a direction is instant; the builder body below **cross-fades** (`motionFast` 150ms) to that direction's mode/action/granularity. Above the body, the **active direction label** ("Up" / "Down" / "Left" / "Right", Heading 20) names the current target.

### 2 — Mode picker (plain language) (GEST-01, GEST-03)
- Below the active-direction label: a **"Mode"** field label (Label 14 DemiBold) and **four mode pills** (each `controlRowHeight` 40, ≥44px effective hit area), in this fixed order with these exact plain-language labels (locked CONTEXT mapping):
  1. **"Repeat while moving"** → daemon `OnInterval` (`IntervalGesture`) — fires repeatedly as you keep moving (GEST-03).
  2. **"Do once when moved far enough"** → daemon `OnThreshold` / `OnRelease` — fires a single time past a threshold.
  3. **"Adjust proportionally"** → daemon `Axis` (`AxisGesture`) — maps movement amount to a scroll/axis amount.
  4. **"Nothing"** → daemon `NoPress` — direction does nothing.
- Pills are single-select. Selected pill = `accentTint` background + accent text + DemiBold; unselected = `hairline` border, `foreground` text → `hoverTint` on hover. Selecting a mode is **live-apply**: it calls the daemon mode-switch mechanism (the phase's first daemon extension — a per-direction "set gesture mode" two-step mirroring `ButtonsModel.setAction`) immediately, then marks `ConfigState` dirty.
- **Progressive disclosure:** the Action and Granularity sub-sections render **only when the chosen mode needs them**:
  - "Repeat while moving" → shows **Action** + **Granularity** (interval).
  - "Do once when moved far enough" → shows **Action** + **Granularity** (threshold).
  - "Adjust proportionally" → shows **Granularity** (multiplier/threshold) only — no discrete action.
  - "Nothing" → shows neither; the preview reads the empty-direction sentence.

### 3 — Action sub-section (GEST-01)
- Shown for the two discrete modes. Reuses the **exact same action-picker entry point** as button reassignment — a compact action chooser (Keystroke via `KeyCaptureField`, DPI change/cycle, Host switch, Profile switch, SmartShift / Hi-res toggle, None) feeding the gesture's `SetAction`. Do **not** build a parallel picker; surface the existing categorized chooser scoped to "the action this direction fires".
- Field label: **"Action"** (Label 14 DemiBold). The chosen action shows a one-line summary (Body 16) + its action-type glyph, with the accent current-action dot.

### 4 — Granularity slider (GEST-02) — the bug-fix affordance
- Field label: **"Granularity"** (Label 14 DemiBold). A **slider** (reusing the Pointer-tab DPI-slider visual: `hairline` unfilled track, accent fill, accent thumb, accent focus ring) over the mode's underlying `interval` / `threshold` / `axis_multiplier`.
- To the right of the slider: a **live human readout** (Label 14 Regular, tabular-stable, `mutedForeground`) that translates the raw HID++ value into plain language — **"~1 step per X of movement"** (e.g. "~1 step per small flick" / "~1 step per long swipe"), NOT a raw number. The slider's leftmost stop is the **sane default that fixes the motivating bug** ("one flick = exactly one desktop / one volume tick", GEST-02); moving right makes each step require more movement (coarser); the daemon clamps to valid HID++ units.
- Direction of meaning must be stated in copy, not left implicit (see preview + helper).

### 5 — Live preview sentence (GEST-04) — first-class affordance
- A **preview card** spanning the panel width (`accentTint` surface, `hairline` border, `spacingLg` padding, 8px radius), pinned **directly below the builder body**, containing a small `gesture` glyph + a **Body 16 / Regular, `foreground`** sentence composed in C++ from {direction, mode, action, granularity} and exposed as one NOTIFYable string the QML binds to. It **updates as the user builds** (mode/action/granularity change) — this is the explicit GEST-04 requirement and the legibility centerpiece.
- The sentence states **when** and **how often** the action fires, in plain language. Examples (copy table below has canonical templates):
  - Repeat-while-moving + Next desktop: "Moving up keeps switching desktops as long as you keep moving — about one desktop per small flick."
  - Do-once + Volume up: "Moving up far enough raises the volume by one step. Keep it to a single flick for one step at a time."
  - Adjust proportionally + scroll: "Moving up scrolls in proportion to how far you move."
  - Nothing: "Moving up does nothing."
- The preview animates its text swap with a `motionFast` 150ms opacity cross-fade (no layout jump — the card height is stable / it wraps, it does not collapse).

### 6 — Clear this direction (destructive-lite)
- A small **"Clear"** affordance per active direction (a `ToolButton`, `mutedForeground` → `destructive` on hover with `destructiveTint` bg) that sets the direction to "Nothing" (`NoPress`). It is **not** a full confirmation dialog (a single direction reset is low-stakes and live-applied; the global Unsaved pill + Save is the real safety net). It is the only destructive-colored element in the builder.

### Live-apply, dirty, Save (inherited — CONF seam)
- **No Save button inside the builder.** Every change (mode switch, action set, granularity drag-release) applies to the daemon live via the gesture model and calls the existing `ConfigState.markDirty()`. The persistent **warning-colored "Unsaved changes"** pill and the single accent **Save** button (polkit-gated `.Config.Save`) in the window toolbar are the **same** Phase 3 elements — Phase 4 wires into them, it does not add a second save path. Save error / success copy is inherited verbatim from Phase 3.

### Iconography (new SVG glyphs to add, same monochrome single-path style)
`gesture` (a directional cross / swipe arrows badge — the category + preview-card glyph). The four direction arrows may reuse a single `arrow` glyph rotated 0/90/180/270 rather than four assets. All tintable via `Theme.foreground` / `mutedForeground` / `accent` / `destructive`. Existing glyphs (`keystroke`, `dpi`, `host`, `profile`, `smartshift`, `hires`, `disabled`) are reused unchanged for the gesture's Action sub-picker.

## Motion Contract

Reuse the inherited budget (120–250ms, ease-out, no overshoot, no spring/bounce). All animations interruptible/re-targetable.

| Interaction | `Theme` token | Duration | Curve |
|-------------|---------------|----------|-------|
| Gesture category expand/collapse | `motionAdd` | 220ms | `OutCubic` |
| Direction cell hover / active highlight | `motionFast` | 150ms | `OutCubic` |
| Direction switch → builder body cross-fade | `motionFast` | 150ms | `OutCubic` |
| Mode pill select state | `motionFast` | 150ms | `OutCubic` |
| Granularity slider thumb / fill | `motionFast` | 150ms | `OutCubic` |
| Preview sentence text cross-fade | `motionFast` | 150ms | `OutCubic` |
| (Inherited) Unsaved → Saved confirmation | `motionBase` | 200ms (after ~2s hold) | `OutCubic` |

Honor a reduced-motion preference if the platform exposes one (fall back to instant). Durations stay subtle so live state never reads as instability.

## Copywriting Contract

Tone: plain, action-oriented, second person, English, sentence case, no jargon, no emoji. Errors state problem AND next step. Always distinguish "applies live" from "saved to disk" (inherited mental model). Plain-language mode names are **locked by CONTEXT** — do not rename.

| Element | Copy |
|---------|------|
| Category row label | **Gesture** |
| Builder intro helper (under category, muted) | **Pick a direction, then choose what it does.** |
| Active-direction labels (Heading) | **Up** · **Down** · **Left** · **Right** |
| Mode field label | **Mode** |
| Mode option 1 (`OnInterval`) | **Repeat while moving** |
| Mode option 2 (`OnThreshold`/`OnRelease`) | **Do once when moved far enough** |
| Mode option 3 (`Axis`) | **Adjust proportionally** |
| Mode option 4 (`NoPress`) | **Nothing** |
| Action field label | **Action** |
| Action not yet chosen (helper, muted) | **Choose what this direction does.** |
| Granularity field label | **Granularity** |
| Granularity readout (template) | **~1 step per {amount} of movement** (e.g. "~1 step per small flick", "~1 step per long swipe") |
| Granularity helper (muted, Label) | **Lower means each small movement counts as one step. Higher means you move farther per step.** |
| Primary CTA | **(inherited) Save** — no new CTA; the gesture builder has no Save button of its own |
| Unsaved indicator | **(inherited) Unsaved changes** (warning pill) |
| Clear-direction affordance | **Clear** · tooltip: **Set this direction to do nothing** |
| Empty-direction preview (Nothing) | **Moving {direction} does nothing.** |
| Preview — Repeat while moving | **Moving {direction} keeps {action} as long as you keep moving — about one step per {amount}.** |
| Preview — Do once when moved far enough | **Moving {direction} far enough {action} once. A single flick does one step.** |
| Preview — Adjust proportionally | **Moving {direction} {action} in proportion to how far you move.** |
| Capability-absent (button has no gestures) | category simply **hidden** — no placeholder copy |
| Save error (polkit denied) — inherited | **Couldn't save — authorization was declined. Your changes are still applied live; click Save to try again.** |
| Save error (daemon/D-Bus failure) — inherited | **Couldn't save to disk. The daemon may be unavailable — check that logid is running, then try again.** |

The `{action}` token is the plain-language verb phrase for the chosen action (e.g. "switches a desktop", "raises the volume", "scrolls", "changes DPI"). The model composes these so QML only binds the finished sentence. Never surface raw daemon mode names (`OnInterval`, `Axis`) or raw HID++ units to the user.

## Accessibility & States Checklist (per interactive component)

Every control defines: **default · hover · focus (keyboard, 2px accent ring) · active/selected · disabled (capability-gated) · error**. Specifically:
- The 4 direction cells, 4 mode pills, granularity slider, action controls, and Clear affordance are all keyboard-reachable (Tab order; arrow keys traverse the direction cross and mode pills; Enter/Space activate).
- Minimum **44px effective hit target** on every direction cell / pill / control (invisible padding where the visual is smaller).
- State is **never color-only**: the active direction is also named (Heading label) and the configured dot is paired with a non-"Nothing" mode/action summary; the preview sentence carries the full meaning in words; the Unsaved pill carries text, not just warning color.
- `Accessible.role` / `Accessible.name` / `Accessible.description` set so Orca/AT-SPI announces e.g. "Up direction, Repeat while moving, switches a desktop, about one step per small flick". The preview sentence updates `Accessible.name` when it changes.
- Text/background contrast ≥ 4.5:1 (≥3:1 for ≥20px/600) in both light and dark, verified against the inherited token pairs.
- Granularity readout uses **tabular-stable width** (TextMetrics) so dragging never reflows the panel.
- All strings wrapped in `qsTr()`.
