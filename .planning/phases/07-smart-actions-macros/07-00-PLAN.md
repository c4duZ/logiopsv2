<interfaces>
<!-- The contracts these RED tests encode. Plans 01/02 implement against them. -->

Daemon step model (the sequencer Plan 01 will build, reusing run_task_after):
  A Smart Action holds an ORDERED list of steps. Step kinds:
    - Keypress  { keys: [evdev KEY_* ...] }   (press+release, like KeypressAction)
    - Text      { text: "literal string" }    (typed character-by-character)
    - Delay     { durationMs: int >= 0 }       (inter-step pause)
    - Launch    { target: "app-or-url string", kind: APP|URL }  (DELEGATED — never run by daemon)
  Firing: steps execute in index order; a Delay step schedules the remainder via
  run_task_after(delay) (NON-blocking — never sleep on the HID/event thread).

GUI SmartActionModel (Plan 02) — logic-free-QML brain:
  - rowCount = number of steps; per-step roles: kind, summary, payload.
  - insertStep(kind), removeStep(row), moveStep(from,to) keep a stable ordering.
  - A Launch step carries an isDelegated=true flag the model exposes so the UI
    (and the daemon contract) treat it as "session-helper only".
</interfaces>
</context>
