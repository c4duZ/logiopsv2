<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user/QML → model | step edits are validated in the C++ model (Plan 02); QML carries no logic |
| Launch/URL step → execution | must visibly route to the user session, never root |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-03-01 | Spoofing | Launch/URL step UI | mitigate | Steps with isDelegated render a "runs in your user session" badge so the user understands it is not a root action (transparency for MACRO-02) |
| T-7-03-02 | Elevation of Privilege | builder dispatch | mitigate | QML only calls model methods; no QProcess/openUrl in QML — execution stays on the daemon→session-helper path verified in the UAT (no root-spawned child; helper executes) |
| T-7-03-03 | Tampering | step payload fields | accept | Field-level value sanity (e.g. delay >= 0) is enforced by the model (Plan 02); the QML spinner bounds are a UX convenience, not the security control |
</threat_model>
