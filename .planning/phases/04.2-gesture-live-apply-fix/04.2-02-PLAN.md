<objective>
Fix the read-back half of Bug A's symptom set (GEST-01): when the user opens the gesture
builder on a direction that is ALREADY configured, the GUI must reflect the existing mode
AND the bound action — not show the blank "choose what this direction does" / "doing what
you choose" copy. The daemon already exposes the full read-back surface for a cfg-loaded
gesture (debug file: button5/gestures/up exposes BOTH .Gesture.OnRelease AND
.Action.Keypress; GetKeys -> "KEY_VOLUMEUP"). After Plan 01, a LIVE-set gesture exposes the
same surface. Today GestureModel::seedFromDaemon resolves the MODE (probeDirection) and the
granularity PARAM (seedParam) but never reads back which ACTION is bound, so DirectionState.
actionType stays empty and the preview/picker read as unconfigured even when the daemon has
a real action. Extend the read-back to introspect/parse the present `.Action.<type>` child
on each configured direction and populate `actionType` (and, for Keypress, enough to label
it) so the builder opens reflecting current state.

Purpose: GEST-01 — the GUI reads back an existing gesture's mode + action.
Output: GestureModel read-back that resolves mode + bound action; a test pinning it.
</objective>
