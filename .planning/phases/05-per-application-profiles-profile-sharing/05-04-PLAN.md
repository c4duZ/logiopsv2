Give the user the Options+-style UI to manage per-application profile switching:
add/edit/remove app-match rules (window-class or executable → profile), pick the
default profile, and export/import profiles as shareable files. The model writes the

the export/import buttons drive Plan-03 ProfileIO (PROF-04). Ends with an on-hardware
UAT checkpoint because focus-following + file sharing are inherently runtime/visual.

     It must serialize VIA the SAME RuleStore schema the helper uses (Plan 02) so the
     file the GUI writes is the file the helper reads. If RuleStore is daemon-helper-only,
     re-use its JSON shape exactly (version/defaultProfile/rules[field,pattern,profile]). -->
class AppRulesModel : public QAbstractListModel {
  // roles: FieldRole (windowClass|executable), PatternRole (s), ProfileRole (s)
  Q_INVOKABLE void addRule(const QString& field, const QString& pattern, const QString& profile);
  Q_INVOKABLE void updateRule(int row, const QString& field, const QString& pattern, const QString& profile);
  Q_INVOKABLE void removeRule(int row);
  Q_PROPERTY(QString defaultProfile ...)  // set/get; persisted
  // every mutation persists to app-profiles.json AND notifies (the helper hot-reloads)
};
class ProfileSharing : public QObject {  // PROF-04 bridge
  Q_INVOKABLE bool exportProfile(const QString& profileName, const QUrl& toFile);
  Q_INVOKABLE QString importProfile(const QUrl& fromFile);  // returns imported name or "" + sets lastError
  Q_PROPERTY(QString lastError ...)
};

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GUI → app-profiles.json | The GUI writes the rule file the non-root helper consumes (same user, user-owned path) |
| imported file → GUI apply | Imported profile validated by ProfileIO before any .Device setter call |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Tampering | imported profile applied to device | mitigate | ProfileSharing.importProfile validates the envelope (ProfileIO throws on bad version) and surfaces lastError; only applies on a clean parse |
| T-05-04-02 | DoS | malformed rule pattern | mitigate | Patterns are plain substrings (no regex eval in the engine) so a hostile pattern cannot cause catastrophic backtracking |
| T-05-04-03 | Tampering | export switching the live profile | accept | exportProfile may SetProfile to read a named profile back; this is the same authorized switch the user already performs in the Profiles tab — no new privilege, and the active profile is restored by the user if needed |
</threat_model>
