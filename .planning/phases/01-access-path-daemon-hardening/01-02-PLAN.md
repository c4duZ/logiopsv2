    Replace the file content with EXACTLY this (per RESEARCH "Target content"), keeping `own` root-only
    and placing the group `<allow>` AFTER the default `<deny>` so the explicit allow wins:
    ```xml
    <!DOCTYPE busconfig PUBLIC
     "-//freedesktop//DTD D-BUS Bus Configuration 1.0//EN"
     "http://www.freedesktop.org/standards/dbus/1.0/busconfig.dtd">
    <busconfig>
      <policy context="default">
        <deny receive_sender="pizza.pixl.LogiOps"/>
      </policy>

      <!-- Daemon owns the name as root -->
      <policy user="root">
        <allow own="pizza.pixl.LogiOps"/>
        <allow send_destination="pizza.pixl.LogiOps"/>
        <allow receive_sender="pizza.pixl.LogiOps"/>
      </policy>

      <!-- Non-root members of the logiops group may call and receive signals,
           but may NOT own the name -->
      <policy group="logiops">
        <allow send_destination="pizza.pixl.LogiOps"/>
        <allow receive_sender="pizza.pixl.LogiOps"/>
      </policy>
    </busconfig>
    ```
    Do NOT add `<allow own=...>` to the group policy — name ownership stays root-only (locked decision).
    The `logiops` group itself is created by packaging (Phase 9); for this phase's smoke test the tester
    runs `groupadd logiops && usermod -aG logiops <user>` and re-logs-in. Note that in the SUMMARY.
