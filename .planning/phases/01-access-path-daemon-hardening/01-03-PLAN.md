    Edit the [Service] block of src/logid/logid.service.in to KEEP `Type=simple`, the existing
    `ExecStart=...`, and `User=root`, and ADD the hardening directives verbatim (per RESEARCH target):
    ```ini
    # --- Hardening (Phase 1) ---
    NoNewPrivileges=yes
    ProtectSystem=strict
    ProtectHome=yes
    PrivateTmp=yes
    ReadWritePaths=/etc/logid.cfg
    RestrictAddressFamilies=AF_UNIX AF_NETLINK
    CapabilityBoundingSet=
    ProtectControlGroups=yes
    ProtectKernelTunables=yes
    ProtectKernelLogs=yes
    ProtectKernelModules=yes
    RestrictRealtime=yes
    LockPersonality=yes
    MemoryDenyWriteExecute=yes
    ```

    CRITICAL — do NOT add these (they break the daemon's purpose, per RESEARCH):
    - `PrivateDevices=yes` (hides /dev/hidraw* and /dev/uinput — DO NOT USE)
    - `DeviceAllow=` / `DevicePolicy=closed` (hidraw nodes are dynamic — leave default)
    - Omitting `AF_NETLINK` (would break udev hotplug)

    Pairing rule (mandatory): `ProtectSystem=strict` mounts /etc read-only, so
    `ReadWritePaths=/etc/logid.cfg` MUST stay — without it save() fails EROFS.

    Open question to surface in the SUMMARY (RESEARCH Pitfall 2 / A7): if save() fails to write under
    the hardened unit because libconfig writes via temp+rename in /etc, widen to `ReadWritePaths=/etc`.
    Start with the file-scoped path and only widen if a real hardware test shows EROFS. The runtime
    authorized-save check that exercises this pairing lives in Plan 06 Task 3 (an authenticated Save
    under this hardened unit must actually write /etc/logid.cfg).
  </action>
