<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GUI (non-root) -> root logid daemon over D-Bus | Profile + Save + ClearProfile calls cross into the root daemon |
| Save() -> polkit authority | Privileged disk write is authorization-gated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-04-01 | Elevation of Privilege | GUI bypasses polkit to write /etc/logid.cfg | mitigate | GUI only calls the daemon's polkit-gated Save(); never opens the file; fail-safe DENY already enforced daemon-side (Phase 1) |
| T-3-04-02 | Denial of Service | Save() blocks the daemon (server_lock through polkit prompt); a retry-storm worsens it | mitigate | Save called async (QDBusPendingCallWatcher); button disabled while saving; no auto-retry (RESEARCH Pitfall 4) |
| T-3-04-03 | Repudiation | a denied Save silently looks like success, user thinks changes persisted | mitigate | Error reply mapped to explicit auth-declined copy stating "changes are still applied live"; dirty stays set until a real success |
| T-3-04-04 | Tampering | ClearProfile on the wrong profile wipes user config unexpectedly | mitigate | Restore gated behind a confirmation Dialog naming the device + "can't be undone"; acts on the active profile only |
| T-3-04-05 | Information Disclosure | unsupported hand-added cfg keys silently dropped on first Save | accept | Documented behavior (RESEARCH A5); round-trip test proves no schema-known value loss; optional user-facing note in Save copy |
</threat_model>
