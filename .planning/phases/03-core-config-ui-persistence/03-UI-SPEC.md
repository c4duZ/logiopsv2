# Phase 3 — UI Design Contract

> Visual and interaction contract for the core Options+-style configuration GUI.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack note:** This is a desktop **Qt 6.4.2 + QML / Qt Quick Controls 2** app
> (`src/logiops-gui/`). All tokens below are expressed in terms QML consumes
> (`Theme.qml` singleton properties, `font.pixelSize`, `Easing` curves). There is
> NO web stack — no Tailwind, no CSS, no shadcn. The shadcn/registry gate is **not
> applicable** and the Registry Safety section is marked accordingly.
>
> **Extend, do not replace:** Phase 2 already shipped `src/logiops-gui/qml/Theme.qml`
> as a faithful realization of the project's prior UI-SPEC. This document is the
> Phase 3 superset: it RE-DECLARES the existing tokens verbatim (so the checker can
> validate against one file) and ADDS the new component / interaction / motion /
> copy contracts that Phase 3 introduces. Executors must reuse existing `Theme.*`
> tokens and only add the new tokens named in the "New tokens" subsections.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Qt Quick Controls 2, not a web design system) |
| Preset | not applicable |
| Component library | Qt Quick Controls 2 (`QtQuick.Controls`) with custom-styled controls; tokens centralized in `Theme.qml` singleton |
| Icon library | In-tree monochrome SVG glyphs under `src/logiops-gui/icons/` (currently `mouse`, `keyboard`, `battery`, `charging`); Phase 3 adds the glyphs listed in "Iconography" below, drawn in the same single-path, `currentColor`-tintable style |
| Font | System default font (`Qt.application.font` / platform default — e.g. Cantarell/Noto on GNOME, Noto Sans on KDE). No bundled font; weights limited to Regular(400) + DemiBold(600) which are universally available |
| Control style | `QtQuick.Controls` style is the app default; controls are tinted via `Theme` tokens rather than a Qt style theme, matching the Phase 2 approach |

**Theme mode:** Light/dark resolved at runtime from `SystemPalette.window.hslLightness < 0.5` (Qt 6.4.2 has no `colorScheme`). Every color token below is a light/dark PAIR. Do not hard-code colors in components — bind to `Theme.*`.

## Spacing Scale

Existing 8-point scale (all multiples of 4) — declared in `Theme.qml`, reused unchanged:

| Token | `Theme` property | Value | Usage |
|-------|------------------|-------|-------|
| xs | `spacingXs` | 4px | Icon gaps, callout-to-line gap, inline chip padding |
| sm | `spacingSm` | 8px | Compact spacing: label↔control, slider↔value readout |
| md | `spacingMd` | 16px | Default control row spacing, card inner padding, tab content gap |
| lg | `spacingLg` | 24px | Section padding, detail-pane margins, gap between config sections |
| xl | `spacingXl` | 32px | Major layout gaps (device render ↔ binding list) |
| 2xl | `spacing2xl` | 48px | Major section breaks |
| 3xl | `spacing3xl` | 64px | Page-level spacing / large empty-state padding |

**New layout tokens (add to `Theme.qml`):**

| Token | `Theme` property | Value | Usage |
|-------|------------------|-------|-------|
| Tab bar height | `tabBarHeight` | 48px | Top tab strip (≥44px hit target) |
| Control row height | `controlRowHeight` | 40px | Slider / toggle / combo rows |
| Touch/click min target | (use existing `rowHeight` 56 / min 44) | 44px | Minimum for any clickable hotspot, tab, button |
| Detail panel (button reassign) width | `actionPanelWidth` | 360px | Non-modal side/detail reassignment panel |
| Detail panel min | `actionPanelMin` | 320px | |
| Device render max width | `deviceRenderMax` | 420px | Caps the SVG device art column |
| Button hotspot min size | `hotspotMin` | 32px | Minimum clickable hotspot (≥44 effective via invisible padding) |
| Dialog max width | `dialogMaxWidth` | 440px | Restore-defaults / unsaved-changes confirm dialogs |

Exceptions: button hotspots may render visually as small as `hotspotMin` (32px) but MUST carry an invisible ≥44px hit area (`MouseArea` padded) for accessibility.

## Typography

Existing scale — exactly **4 sizes**, exactly **2 weights**, declared in `Theme.qml`, reused unchanged. Line heights are a contract (set via QML `lineHeight` / `lineHeightMode: Text.ProportionalHeight`):

| Role | `Theme` property | Size | Weight | Line Height |
|------|------------------|------|--------|-------------|
| Display | `displaySize` | 28px | DemiBold (`weightMedium` 600) | 1.2 (headings) |
| Heading | `headingSize` | 20px | DemiBold (`weightMedium` 600) | 1.2 |
| Body | `bodySize` | 16px | Regular (`weightRegular` 400) | 1.5 |
| Label | `labelSize` | 14px | DemiBold (`weightMedium` 600) for section/field labels; Regular for helper/sub-text | 1.4 |

Rules:
- **No new sizes or weights.** All Phase 3 text maps onto these 4 roles. Tab labels = Label(14). Control field labels = Label(14, DemiBold). Slider value readouts = Body(16). Section headers ("Pointer", "Scroll", "Buttons") = Heading(20). Device name = Display(28). Helper/disabled-reason tooltips, "unsaved changes" hint, empty/error copy = Label(14) or Body(16) in `mutedForeground`.
- Numeric DPI/threshold readouts use **tabular-stable width** (Phase 2 pattern: `TextMetrics` for fixed width since `font.features` tnum is Qt 6.7+). Reserve max-glyph width so sliding values do not reflow.
- All user-facing strings wrapped in `qsTr()`.

## Color

Existing 60 / 30 / 10 split — declared in `Theme.qml` as light/dark pairs, reused unchanged:

| Role | `Theme` property | Light | Dark | Usage |
|------|------------------|-------|------|-------|
| Dominant (60%) | `dominant` | `#F5F6F8` | `#1C1E22` | Canvas, detail/config pane background, tab content background |
| Secondary (30%) | `secondary` | `#FFFFFF` | `#26292E` | Sidebar, cards, the non-modal reassign panel surface, dialog surface, control "wells" |
| Hairline | `hairline` | `#E3E6EB` | `#34383F` | 1px dividers, section separators, card borders, tab underline track, slider track (unfilled) |
| Accent (10%) | `accent` | `#2D7DF6` | `#4C92FF` | See reserved list below |
| Foreground | `foreground` | `#1B1D21` | `#ECEEF1` | Primary text, control labels, enabled glyphs |
| Muted foreground | `mutedForeground` | `#6B7280` | `#9AA1AC` | Sub-lines, helper text, disabled-button labels, "—" placeholders, empty/error copy |
| Charging / healthy | `charging` | `#2BA84A` | `#46C46A` | Battery healthy, "saved" success confirmation tick |
| Warning | `warning` | `#E8A23D` | `#F0B252` | Low battery, **unsaved-changes** indicator |
| Accent tint | `accentTint` | accent @12% | accent @12% | Selected tab/row background, selected DPI-cycle chip background, active-profile pill background |
| Hover tint | `hoverTint` | foreground @6% | foreground @6% | Hover background on hotspots, list rows, tabs, chips |

**New semantic token (add to `Theme.qml`):**

| Role | `Theme` property | Light | Dark | Usage |
|------|------------------|-------|------|-------|
| Destructive | `destructive` | `#D14343` | `#E06363` | **Destructive actions ONLY** — Restore-defaults confirm button, remove-DPI-preset / remove-profile affordances, the "discard unsaved changes" path |
| Destructive tint | `destructiveTint` | destructive @12% | destructive @12% | Destructive dialog accent strip / icon background |

**Accent reserved for (explicit list — never "all interactive elements"):**
1. The currently **selected tab** (underline indicator + label color) and selected sidebar device row.
2. The **focus ring** on the keyboard-focused control (slider thumb, toggle, combo, button).
3. The **primary `Save` button** fill (the one phase-primary CTA).
4. The **filled portion** of DPI / SmartShift sliders (track-fill + thumb).
5. The **ON** state of toggles/switches (SmartShift on, hi-res on, thumbwheel divert).
6. The **selected/active DPI-cycle preset chip** and the **active profile pill** (via `accentTint` background, accent text).
7. The pressed-button **highlight ring** on the device render hotspot that is currently being edited.

Everything else (secondary buttons "Cancel", "Add preset", "Capture keys"; toggles in OFF state; unselected tabs; binding-list rows) uses `foreground` / `secondary` / `hairline` — NOT accent. Buttons disabled by capability gating use `mutedForeground` on `secondary` with reduced opacity.

**Contrast note:** On `accentTint` backgrounds, text stays `foreground` (not white) to preserve contrast in both modes — matching the Phase 2 selected-row rule.

## Component & Interaction Contract

This is the prescriptive heart of the phase. Executors implement against these states.

### Tabbed layout (UI-01)
- The **Populated** detail pane (replacing today's read-only `DetailPane.qml`) becomes a header + **tab strip** + tab content.
- Header (persistent above tabs): device icon (40px), name (Display 28), model sub-line (Label 14 muted), live battery/connection chip (reuse Phase 2 battery glyph + threshold colors).
- Tabs (left-to-right, `tabBarHeight` 48): **Buttons** · **Pointer** · **Scroll** · **Profiles**. A tab is **omitted entirely** (not shown disabled) only if the whole capability is absent for that device kind; individual sub-sections inside a tab are capability-gated per CONTEXT (shown-disabled-with-tooltip or hidden — see each section).
- Tab indicator: 2px accent underline that **slides** between tabs (`motionBase` 200ms, `OutCubic`). Selected label = accent + DemiBold; unselected = `mutedForeground` Regular → `foreground` on hover (`hoverTint` bg).
- Tab content cross-fades on switch (`motionFast` 150ms opacity), consistent with the existing detail-pane cross-fade.

### Device render + button mapping (BTN-01, BTN-04 — "Buttons" tab)
- Two synced views side-by-side (`spacingXl` gap; stack vertically below `windowMinWidth` if cramped):
  1. **Device render**: per-model SVG (max width `deviceRenderMax` 420) with **clickable hotspots**. Fallback: generic annotated mouse/keyboard diagram when no model artwork exists.
  2. **Binding list**: a synced list of *button → current binding* rows (`rowHeight` 56), each row showing button name (Label 14 DemiBold) + current binding summary (Body 16) + a small action-type glyph.
- Hotspot states:
  - **Default**: subtle outline (`hairline`) or invisible until hover.
  - **Hover**: `hoverTint` fill + `foreground` outline; cursor `PointingHand`. The synced binding-list row highlights in tandem (and vice-versa — hovering a list row highlights its hotspot).
  - **Selected/editing**: accent ring (item #7 in reserved list) while its reassign panel is open.
  - **Unsupported / non-remappable**: rendered but `mutedForeground` + reduced opacity, NOT clickable, with a `ToolTip` explaining why (copy below). Hit area returns no action.
- **Click → non-modal reassign panel** (CONTEXT: not a blocking modal): the device render stays visible; a side/detail panel (`actionPanelWidth` 360) slides in from the right or expands inline (`motionAdd` 220ms width/opacity, `OutCubic`). Closing it deselects the hotspot.

### Action picker / reassignment panel (BTN-02, BTN-03, HOST-01)
- Panel header: the button being edited (Label 14 muted) + its name (Heading 20).
- **Categorized action list** (CONTEXT order): Keystroke · DPI (Change / Cycle) · Host switch · Profile switch · SmartShift toggle · Hi-res toggle · **None (disabled)**. Render as grouped rows; the current action is marked with an accent check/dot.
- **Keystroke (BTN-02)**: a **key-capture widget** with two modes:
  - "Press keys now" capture button — entering capture shows an accent focus ring + live readout of captured modifiers+key (Body 16, tabular-stable); `Esc` cancels capture.
  - A manual **modifier checkboxes + key combo** fallback editor beneath it.
- **DPI change vs cycle**, **Host switch** (numbered host slots 1/2/3 + next/prev cycle option), **Profile switch**: each reveals a compact inline editor when its category is chosen.
- "None (disabled)" maps to the daemon `NullAction`; selecting it clears the binding and the list row shows muted "Disabled".
- Apply is **live** (see persistence). Panel has no Save button of its own.

### Pointer / DPI (DPI-01..03 — "Pointer" tab)
- **Sensitivity slider** (DPI-01): bounded by the device's reported min/max (read from daemon — never hard-coded). Track unfilled = `hairline`, filled = accent, thumb = accent with focus ring on keyboard focus. Live numeric readout (Body 16, tabular-stable) to the right; readout shows the unit (`DPI`). Step = device-reported step or sane default.
- **DPI-cycle editor** (DPI-02 / DPI-03): a list of preset **chips/rows**, each = a DPI value + an editable **label** (Label 14). Add ("+ Add preset", secondary button) / remove (destructive affordance, `destructive` on hover/confirm) per row. The active preset chip uses `accentTint` bg + accent text. Reordering is out of scope this phase unless trivial.

### Scroll (SCR-01..03 — "Scroll" tab) — every section capability-gated
- **SmartShift** (SCR-01): on/off **toggle** (accent when ON) + **threshold slider** + **torque slider**. Sliders disabled/greyed while toggle is OFF. Entire section **hidden** when the device lacks SmartShift (mirror daemon `UnsupportedFeature`).
- **Hi-res scroll** (SCR-02): on/off toggle + **invert-direction** checkbox. Section hidden when unsupported.
- **Thumbwheel** (SCR-03): section shown only on supported devices; exposes **divert** + **invert** toggles plus **left / right / tap** action mappings (each reuses the same action-picker entry point as buttons).
- Gating rule (project-wide): if a capability is *device-kind-irrelevant* (e.g. thumbwheel on a keyboard) → **hide**. If a *remappable button* is present-but-not-remappable → **show disabled + tooltip** (per CONTEXT). Sliders/toggles inside an unsupported feature section → hide the whole section.

### Profiles, live-apply, Save, restore (PROF-01, CONF-01, CONF-02 — "Profiles" tab + global)
- **Profiles tab**: list of manual profiles; **create** ("+ New profile" secondary button → inline name field), **name** (inline-editable, Label 14), **switch** (selecting a profile pill applies it live; active profile = `accentTint` pill + accent text). Manual profiles only this phase.
- **Live-apply model**: every change applies to the daemon instantly (single source of truth). State stays in sync via the existing signal-driven model.
- **Unsaved-changes indicator**: a persistent **`warning`-colored** dot/pill in the window header/toolbar reading "Unsaved changes" (Label 14) once any change has been applied-but-not-persisted. Clears to a brief `charging`-colored "Saved" confirmation (tick, fades after ~2s, `motionBase`).
- **Save** (the phase primary CTA): a single accent-filled **`Save`** button (in the header/toolbar). On click it calls the daemon's polkit-gated `Save()` over D-Bus. While the polkit prompt is pending, the button shows a `BusyIndicator` and is disabled. On denial/error → inline error copy (below). On success → "Saved" confirmation, unsaved indicator clears.
- **Restore defaults** (CONF-02): a per-device secondary/destructive button "Restore defaults…" (trailing ellipsis = opens dialog). Opens a **confirmation dialog** (`dialogMaxWidth` 440): destructive-styled confirm button (`destructive`), Cancel (secondary). Resets that device's config section via the daemon round-trip.

### Iconography (new SVG glyphs to add, same monochrome single-path style)
`keystroke` (keycap), `dpi` (gauge/arrows), `host` (monitors), `profile` (layers), `smartshift`, `hires` (scroll wheel), `thumbwheel`, `disabled` (slash circle), `save` (check/disk), `restore` (counter-clockwise arrow), `add` (plus), `remove` (trash/minus). All tintable via `Theme.foreground` / `mutedForeground` / `destructive`.

## Motion Contract

Reuse the existing budget (120–250ms, ease-out, no overshoot). No spring/bounce.

| Interaction | `Theme` token | Duration | Curve |
|-------------|---------------|----------|-------|
| Tab indicator slide | `motionBase` | 200ms | `OutCubic` |
| Tab content cross-fade | `motionFast` | 150ms | `OutCubic` |
| Reassign panel slide/expand | `motionAdd` | 220ms | `OutCubic` |
| Hotspot hover highlight | `motionFast` | 150ms | `OutCubic` |
| Slider thumb / toggle state | `motionFast` | 150ms | `OutCubic` |
| Save → "Saved" confirmation fade-out | `motionBase` | 200ms (after ~2s hold) | `OutCubic` |
| Dialog open/fade | `motionBase` | 200ms | `OutCubic` |

All animations must be interruptible (re-targetable) and must respect a reduced-motion path if added later — for now, durations stay within budget so motion is subtle.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Save** (button). While persisting: a `BusyIndicator`; success transient: **Saved** |
| Unsaved-changes indicator | **Unsaved changes** (warning-colored pill) |
| Buttons tab — reassign panel title | **Reassign button** / sub-line shows the physical button name (e.g. "Middle button") |
| Key-capture prompt | **Press the keys you want to assign** · helper: **Press Esc to cancel** |
| "None" action label | **Disabled** (list row shows "Disabled" in `mutedForeground`) |
| Unsupported button tooltip | **This button can't be reassigned on this device.** |
| Capability-absent section | section simply hidden — no placeholder copy |
| DPI add preset | **+ Add preset** · empty cycle helper: **No DPI presets yet. Add one to cycle through sensitivities.** |
| Empty state — no profiles | heading: **No profiles yet** · body: **Create a profile to save a set of settings you can switch between.** |
| Empty state — device has no remappable buttons | **This device has no reassignable buttons.** |
| Restore defaults button | **Restore defaults…** |
| Restore defaults confirmation (dialog) | title: **Restore default settings?** · body: **This resets {device name}'s buttons, pointer, and scroll settings to their defaults. This can't be undone.** · confirm: **Restore defaults** (destructive) · cancel: **Cancel** |
| Discard unsaved changes (if user switches device / closes with unsaved) | title: **Discard unsaved changes?** · body: **You have changes that haven't been saved to disk. Discard them?** · confirm: **Discard** (destructive) · cancel: **Keep editing** |
| Save error (polkit denied) | **Couldn't save — authorization was declined. Your changes are still applied live; click Save to try again.** |
| Save error (daemon/D-Bus failure) | **Couldn't save to disk. The daemon may be unavailable — check that logid is running, then try again.** |
| Live-apply note (subtle helper, optional) | **Changes apply instantly. Save to keep them after a restart.** |

Tone: plain, action-oriented, second person. Never blame the user. Errors always state the problem AND the next step. Distinguish "applied live" from "saved to disk" everywhere — this is the core mental model of the phase.

## Accessibility & States Checklist (per interactive component)

Every control must define: **default · hover · focus (keyboard, accent ring) · active/on · disabled (capability-gated) · error**. Specifically:
- All hotspots, tabs, sliders, toggles, combos, and buttons reachable by keyboard (Tab order) with a visible accent focus ring.
- Minimum 44px effective hit target (invisible padding on small hotspots).
- Disabled-by-capability controls expose a `ToolTip` reason, never silently dead.
- Text/background contrast ≥ 4.5:1 in both light and dark (verified against the token pairs).
- `qsTr()` on all strings; numeric readouts use tabular-stable width.
